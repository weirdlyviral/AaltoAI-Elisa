## How to compare fairly
Recompute the same statistics on raw data using the release's grouping keys:
time_bucket (same floor), province, radio_access_type, application_category.
Compare only on cells published in the release. Rows whose category became
"OTHER" in the release are compared under "OTHER" on raw, mapped with the same
rule from config. Never print cell-level raw values; report only error
statistics.

## U1 — Headline metric (aggregate release)
For each published cell and each QoE metric (tp_dl_avg, tp_ul_avg,
cont_rtt_radio_avg, http_response_time_avg, http_sr_avg): relative error of the
released median vs the raw median in the same cell.
**Headline:** share of published cells where median tp_dl_avg is within 5% of
raw. **Target: ≥ 90%.** Report the same for every metric, and p10/p90.
State the baseline explicitly: raw = 100% by definition.

## U2 — Coverage (cost of suppression)
- % of raw subscribers, and % of raw rows, that fall into published cells
- the same split by province and radio_access_type, so we can show whether
  suppression hurts rural or rare-technology areas disproportionately
  (a known weakness of threshold-based methods)

## U3 — Answers a real product question
"Where is service quality worst?" Compute on raw vs release:
- Spearman rank correlation of provinces by median tp_dl_avg and by median
  http_sr_avg (aggregated over published cells, weighted by n_subscribers)
- overlap of the bottom-10 (province × radio_access_type × application_category)
  cells by median tp_dl_avg, raw vs release (Jaccard and count)
- the same for 5G-only cells if radio_access_type distinguishes 5G

## U4 — Count accuracy vs ε
From the release, plus re-noising true counts in memory at ε ∈ {0.5, 1, 2}
with the same scale formula the release uses (read it from release_stats):
median and p90 relative error of n_subscribers. This gives the
privacy-utility curve for the pitch. If the M3 scale formula isn't merged yet,
read the scale from release_stats_aggregate.json (or release_stats.json) and
note which version was used.

## U5 — Record release distribution fidelity
Per QoE and volume metric: Wasserstein distance and KS statistic, raw vs record
release, plus the % change in mean and p50/p95. Flag metrics where top-coding
visibly changes the tail.

## Report: docs/utility.md
1. Headline: "Median download throughput is within 5% of raw for X% of
   published cells (target ≥90%)", pass/fail.
2. Tables for U1–U5.
3. Trade-off section: what the aggregate release cannot answer
   (individual journeys, micro-level fault diagnosis, rare cells), and how
   suppression coverage differs by region.
4. Assumptions and limitations (single hour of fabricated data; utility on
   real data may differ).
